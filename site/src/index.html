The idea

The maker is never the checker

Banks call it maker–checker. The kit enforces it in Bob, in git and in the pipeline.

Bob builds

Drafts specs, plans, tasks, code and tests in modes that can each write only their own files. Bob can never sign, never write a check's verdict and never skip a step.

People approve

The business owner signs plans and phases; AppSec accepts risk; the analyst checks the proof. Each sign-off is bound to the exact files it approved, and some decisions stay with people whatever the settings.

Checks verify

Security checks run as Bob writes, at commit and before any testing — built-in ones, and your organisation's own tools. The pipeline runs them again, where nobody can switch them off.

What's in the kit

Everything that makes a spec binding

  • IBM Bob V2 configuration — modes fenced to their own files (Bob's Agent, Plan and Ask included), rules, slash commands, skills and lifecycle hooks.
  • Human sign-offs by terminal command or pull-request comment, verified in the pipeline: right role, not the maker, bound to the files.
  • The automation dial — risk tiers decide who signs and how far Bob may run; locked gates no setting can remove.
  • Shift-left security — secrets, risky code and bad dependencies refused as Bob writes, at commit, before testing and in CI. IBM detect-secrets, HashiCorp Vault Radar or SonarQube plug in through one file.
  • One gate for any CI — node sdd/scripts/ci.mjs pr in Jenkins, Azure DevOps, GitLab or GitHub Actions; no Actions needed.
  • Evidence for auditors — one command assembles who decided what, which test proves which requirement, and what the checks said.

Quick start · five minutes

Clone, then ask "what's next?"

git clone {{REPO}}.git
cd tidewell-sdd-ibm-bob
git config core.hooksPath sdd/scripts/hooks

node sdd/scripts/policy.mjs show   # the automation dial
node sdd/scripts/state.mjs         # where the project is
node sdd/scripts/ci.mjs pr         # the gate every pipeline runs

Then open the folder in IBM Bob, trust it, pick 🧭 SDD Navigator and ask "what's next?". Besides IBM Bob, you need only git and Node.js 22: every script in the kit is plain Node, with nothing else to install.

Bob's configuration (.bob/), the guardrail scripts, the workflows, the governance files and the CI templates. A Security Reviewer, not a bank reviewer; a domain-rules skill that reads whatever domain the specs define.

The example · Tidewell Bank

A fictional UAE bank (AED, English and Arabic): product vision, domain model, 12 feature specs, NFRs, the API contract, and the rules Bob must never break in sdd/specs/domain/. Replace them for insurance, health, retail or the public sector.
